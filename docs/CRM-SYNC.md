# اتصال نذر امام به CRM24

این اتصال قرارداد عمومی API یا جدول‌های سایت را تغییر نمی‌دهد.

- کاربر ذخیره‌شده، حتی بدون ثبت نذر، پس از ورود/ثبت‌نام برای همگام‌سازی مخاطب فرستاده می‌شود. اختلال CRM مانع ورود نیست.
- یک دقیقه بعد از راه‌اندازی و سپس هر ساعت، تمام پرداخت‌های موفق، درخواست‌های نذر با هر وضعیت و کاربران donor با صفحه‌بندی پایدار UUID بررسی می‌شوند. خطای موقت باعث بازآزمایی پس از پنج دقیقه می‌شود؛ خرابی یک صفحه یا مجموعه، بررسی مجموعه‌های دیگر را متوقف نمی‌کند.
- درخواست بدون پرداخت موفق در CRM «در انتظار پرداخت» است. درخواست لغوشده/ردشده با وضعیت «لغو شده» ثبت می‌شود. خطای شبکه پس از درج، با جست‌وجوی کد نذر در دور بعد ترمیم می‌شود.
- تغییر وضعیت درخواست موجودِ بدون پرداخت موفق، ارجاع مخاطب و مسئول همان رکورد را حفظ می‌کند؛ موبایل مخاطب موجود دوباره با سایت تطبیق داده می‌شود. این کار به انتخاب دوباره از میان پرونده‌های هم‌شماره نیاز ندارد. انتخاب مخاطب برای ارتباط مالی جدید همچنان باید بدون ابهام باشد.
- کلید پرداخت CRM کد نذر است، نه شناسه هر تلاش پرداخت. تلاش‌های ناموفق یا تکراری، درآمد موفق جداگانه نیستند.
- تمام نویسنده‌های این اتصال از قفل مشترک MySQL استفاده می‌کنند؛ جست‌وجو و ایجاد مخاطب یا پرداخت زیر همان قفل است. داخل قفل فقط ارتباط CRM انجام می‌شود تا اتصال‌های منتظر، عملیات پایگاه داده نویسنده فعال را مسدود نکنند.
- مخاطب بر اساس موبایل با پشتیبانی از قالب بین‌المللی، فاصله و ارقام فارسی/عربی پیدا می‌شود. برای چند مخاطب هم‌شماره، تنها تطبیق یکتای نام یا پرونده یکتای همان نام با برچسب نذر پذیرفته می‌شود. انتخاب مبهم، خودکار انجام نمی‌شود.
- برچسب `cf_1756=بله` روی مخاطب منتخب موجود تکمیل می‌شود. نام، موبایل، مسئول و منبع اولیه مخاطب حفظ می‌شوند. برای گزارش افراد مرتبط، از برچسب نذر استفاده کنید؛ `leadsource` تاریخچه منبع اولیه ورود است. مخاطب جدید، منبع «سایت نذر امام» می‌گیرد.
- مبلغ CRM ریال است. مبلغ خارج از دقت صحیح امن یا نامعتبر برای بررسی متوقف می‌شود و مبلغ جایگزین ساخته نمی‌شود.
- رکورد مالی تسویه‌شده با مغایرت مبلغ، خودکار بازنویسی نمی‌شود. مغایرت و هویت مبهم در لاگ با شناسه رکورد اعلام می‌شوند؛ نام و موبایل چاپ نمی‌شوند.

## موارد نیازمند بررسی دستی

متغیر `CRM_REVIEW_TRACKING_CODES` فهرست کدهای نذر جداشده با ویرگول است. تا وقتی کدی در این فهرست باشد، تمام مسیرهای همگام‌سازی مالی و بازآزمایی آن را کنار می‌گذارند؛ پرداخت موفقش در سایت و آمار مالی سایت تغییر نمی‌کند. پس از احراز هویت و تصمیم مسئول، کد را از تنظیمات حذف کنید تا همگام‌سازی بعدی دوباره آن را بررسی کند. مقدار واقعی این فهرست در تنظیمات سرور می‌ماند و وارد Git نمی‌شود.

## بررسی پس از دیپلوی

نسخه و commit فعال، پاسخ سلامت سایت و API و پیام `CRM reconciliation completed` را بررسی کنید. سپس خروجی همه درخواست‌ها و کاربران و پرداخت‌ها را با CRM تطبیق دهید. تعداد موارد باقی‌مانده باید فقط با موارد بررسی دستی، مبلغ نامعتبر یا خطای مشخص توضیح داده شود؛ خطای شبکه به‌معنی پایان موفق انتقال نیست.

تست‌های اتصال پس از ساخت API با `node --test apps/api/test/crm-sync.test.cjs` اجرا می‌شوند.
